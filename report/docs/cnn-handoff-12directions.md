## 四、这张图是怎么来的（决定你该怎么用）

**PL 里是一条固定顺序的处理链**（`src/HLS/gesture_preproc.cpp`）：

```
RGB565 640×480
   │
   ├─ ① crop_scale    裁 ROI + 缩放到 96×96（含 RGB→灰度）
   ├─ ② 高斯           3×3 平滑
   ├─ ③ Sobel          梯度
   ├─ ④ 自适应阈值     ★ 二值化在这里
   └─ ⑤ 形态学（闭运算）
   │
   ▼
96×96 uint8，只有 0/255
```

### ⚠⚠ 三个必须知道的点（**不理解这三点会训出没法用的模型**）

**① 二值化的输入是 Sobel 梯度图，不是灰度图**

所以这张图反映的是**边缘**，不是亮度。掌心等平坦区域是黑（0），
手部轮廓是白（255）。

**② 阈值不是固定常数，是全图自适应**

源码里的判决规则（`thresh_stage`，`gesture_preproc.cpp:559-572`）：

```
mean = 全部 9216 个梯度像素之和 / 9216     ← 整数除法
th   = mean + offset                       ← offset 默认 −8
th   夹到 [0, 255]
输出 = (像素 > th) ? 255 : 0                ← 严格大于
```

**所以"亮度整体变化"会被自动抵消** —— 这是它抗光照的原因，
也意味着**你不能靠调图片亮度来造样本多样性**（会被自适应掉）。
要造多样性，改**形状/角度/大小**。

**③ 形态学在阈值之后**

闭运算会把细小的边缘连成块。所以最终图比"纯 Sobel"更**粗**，
细小的边缘可能被吃掉。

> **⚠ 结论：不要自己用 OpenCV 复现这条链。**
> 中间任何一步（Sobel 定点精度、整数舍入、形态学顺序）与硬件有偏差，
> 训练分布和推理分布就对不上，而**这个偏差是静默的**。
> **用我们提供的 golden 工具造数据**（见下节）。

## 五、⭐ 怎么造训练数据（**最省事的路**）

**`gesture_golden.py` 的输出与硬件逐位一致**（板上实测 0/9216 不一致）。
所以**在 PC 上造的数据，分布就是硬件真实产出的分布**。

### 工具在哪

```
完整仓库 complete_project_source/host/gesture_golden.py
⚠ 不在 gesture_pl 里（它属 PC 侧）—— 找 PL 侧要，或从完整仓库取
```

### 造一张

```bash
python gesture_golden.py --input frame.bin --out feature.bin --png preview.png
```

`frame.bin` 是 **640×480 RGB565**（`uint16` 小端，行列优先，614400 字节）。

### 从普通图片造（推荐）

```bash
# 任意图片 → 640×480 RGB565
python capture_frame.py --image 你的图.jpg --out frame.bin --png preview.png

# 算对应的特征图
python gesture_golden.py --input frame.bin --out feature.bin
```

> ⚠ **`--png` 一定要看** —— 它会画出中间结果，能一眼看出
> "手在不在框里""ROI 选得对不对"。本项目因为 ROI 选错吃过很多次亏。

### ⚠ ROI 三处必须一致

生成输入的图 / 板上 `config()` / golden 的 `--roi` —— **差一个就是另一个答案**。
默认 `--roi 160 80 320 320`，但**那个 ROI 会切掉拇指**（实测结论）：
要让五指齐全，`roi_x` 需 ≤ ~100。

## 六、网络：⚠ 动手前先解决 `W2` 爆炸问题

**现有的 MNIST 网络是为 28×28 设计的，直接换成 96×96 会出问题：**

| 输入 | conv 输出 | pool 后 | 展平 | `W2` 参数 |
|---|---|---|---|---|
| 28×28（现） | 24 | 12 | 4,320 | 43 万 |
| **96×96** | 92 | 46 | **63,480** | **635 万** |

**参数涨 14.7 倍，且全压在全连接层上。**

> 这是本项目在 2026-09-23 就识别出的问题，**至今没解决**。

**建议做法**（任选，都不需要我们改 PL）：

| 做法 | 效果 |
|---|---|
| conv 后加**全局平均池化** | 把 46×46×C 直接压成 C，全连接层消失 |
| 加深卷积 / 用 stride 下采样 | 在进全连接前把空间维度降下来 |
| 直接改成**全卷积**结构 | 没有大矩阵乘 |

**⚠ 别硬扛 635 万参数** —— 那正是量化/推理加速最头疼的形态。

## 七、归一化：**别照搬 MNIST 的假设**

| 侧 | 取值范围 |
|---|---|
| 你的训练代码（MNIST） | `uint8` 0–255，**连续灰度** |
| **PL 输出** | `uint8`，**只有 0 / 255** |

**两边"都没归一化"是巧合，不是约定。** 而且分布完全不同：

- MNIST 是**连续灰度**
- 我们的是**二值**（只有两个值）

> **⚠ 所以 MNIST 上训好的权重不能迁移，必须用真实特征图重训。**
> 好消息：用 `gesture_golden.py` 造数据成本可控（见 §五）。

**归一化怎么做由你决定**（比如 `/255` 变成 0/1），**但要固定下来**：
训练和推理必须用同一套。
